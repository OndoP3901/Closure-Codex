# 详细使用指南

日常安装与主题启用步骤见 [README](../README.md)。本文补充设置、排错和源码开发说明。

## 桌宠设置

右键桌宠打开设置面板，内容较多时可在面板内滚动。设置自动保存到 `work/companion-profile`，升级时复制这个文件夹即可保留。

- **Codex 联动**：读取本机 Codex 活动，播放任务动作、场景语音和额度反馈。活动按本机汇总，提示可能来自后台聊天。
- **DSH / WorkBuddy 联动**：通过独立开关接入，共用原 Codex 联动队列；DSH 查询软件内官方钱包，WorkBuddy 查询软件内账号剩余积分。启动与插件安装见[三软件联动说明](COMPANION-INTEGRATIONS.md)。
- **在桌面和其他软件中显示**：开启后，软件最小化时桌宠仍会显示；关闭后，只在已勾选联动软件的主窗口前台显示。
- **开机自启**：默认开启；取消后当前桌宠继续运行，下次登录不再自动启动。升级保留已关闭的选择。
- **位置与外观**：角色可拖动，松开后吸附到工作区边缘。可调整大小、透明度和镜像；找不到角色时可使用「重置位置」。
- **帧率**：30–60 FPS，默认 60 FPS，调整即时生效并保存。
- **对话字号**：12–36 px，默认 24 px。**气泡大小**：60%–160%，默认 100%。两者分别保存，气泡大小不改变角色大小；屏幕空间不足时，文字会临时缩小，空间恢复后使用保存的字号。
- **声音**：普通话、日语、英语和韩语可选，字幕保持简体中文。角色配音和界面音效分别控制。卫戍协议语音仅有普通话和日语，选择英语或韩语时使用普通话。
- **提醒与播报**：鼠标中键点击桌宠，手动查看所有已连接工具的账户余额；不自动弹出余额。工具失败文字提示可单独关闭。

退出入口在右键菜单底部，桌宠没有托盘图标。主动退出后不会自动拉起，意外退出会有限重试；手动启动入口为 `outputs/Start-Closure.cmd`。

### 自定义语音队列

1. 右键桌宠，展开「语音队列」，从「默认队列」切换到「个人队列」。
2. 按场景选择队列，在待选区筛选来源，点击「试听」或「加入」。同一句可以加入多个场景。
3. 点击「移除」删除不需要的台词；个人队列留空可关闭对应场景的语音。
4. 想恢复预设时，切回「默认队列」即可，个人队列仍会保留。

联动时可编辑以下场景；未联动时，单独保存左键互动队列。

| 场景 | 触发条件 | 默认条数 |
| --- | --- | ---: |
| 任务开始 | 当前优先对话开始处理新一轮任务。 | 5 |
| 任务中 | 任务持续约 15 秒后播报一次；左键互动也从此队列轮换。 | 20 |
| 任务完成 | 一轮任务成功结束。 | 14 |
| 启动联动 | 联动桌宠启动并显示后。 | 1 |
| 空闲五分钟 | 连续五分钟没有任务时播报一次。 | 2 |
| 工具调用错误 | 随工具失败提示播报。 | 2 |
| 联动软件提问 | 当前优先对话发出结构化提问。 | 1 |
| 用户提交回答 | 提交结构化提问的表单答案。 | 4 |

默认和个人队列均随机轮换，同一轮内每条播放一次。未联动时，默认左键互动从全部 57 条语音中轮换。

### 额度与用量

余额只在中键点击桌宠时显示，按软件分别列出已启用且连接的账户。DSH 显示官方充值和赠送钱包；WorkBuddy 显示当前账号剩余积分；Codex 显示原有额度或账户余额。未连接项不显示，刷新数据不会自动弹出气泡。

中键点击桌宠时，官方 ChatGPT 登录显示接口提供的剩余百分比与积分；已适配的第三方服务使用本机配置查询余额。余额数据约每分钟更新一次，未连接工具不显示；低额度不自动弹出余额提示。

多个软件或对话并行时，提示、动画和语音统一跟随最近有真实活动的对话。完成、提问、输出和工具执行均更新排序；连接心跳与余额刷新不影响排序。最新对话刚完成时保留其结束状态，其他对话出现新活动后再切换，不补播已略过的旧提示。

## 主题补充说明

- 主题适用于 Windows x64 的 Microsoft Store 版 Codex，不修改官方安装目录、签名或 ASAR。配色、字体、菜单栏和扫描线效果一起加载，无需手动导入。
- 第一次需要从运行中的 Codex 识别实际配置目录。之后直接使用主题快捷方式启动；恢复原外观后，配置识别记录仍保留，再次启用无需提前打开 Codex。
- 从原版快捷方式打开普通 Codex 后，再启用主题通常需要重启一次。操作前请保存工作。
- 保存目录失效时，先正常打开 Codex，再运行主题入口重新识别；多个配置实例无法确定时，关闭多余实例后重试。
- 主题优先使用 Cascadia Mono，中文回退到系统字体。想使用像素字体，可安装 [Fusion Pixel 12px](https://github.com/TakWolf/fusion-pixel-font/releases)，在 Codex 外观设置中选择对应的界面和代码字体。
- 当前已在官方 Codex `26.1120.5083.0` 的独立后台配置中验证主题启动、注入与恢复。未来版本及其他电脑仍可能需要兼容适配。

更多实现细节见[页面主题说明](../outputs/closure-decoration/README.md)。

## 排错

| 问题 | 处理方法 |
| --- | --- |
| 首次启用提示先打开 Codex | 打开 Microsoft Store 版 Codex，等待主界面出现，再运行主题入口。 |
| 主题启动失败 | 保留错误弹窗和日志；需要查看控制台时，运行 `tools\Enable-Codex-Theme.cmd --debug`。 |
| 恢复外观失败 | 运行 `tools\Restore-Codex-Appearance.cmd --debug` 查看输出。 |
| 桌宠不显示 | 确认显示范围设置，或手动运行 `outputs/Start-Closure.cmd`；仍失败时查看 `work/lifecycle.log`。 |
| 气泡或设置显示不全 | 设置面板可滚动；分别调小「对话字号」和「气泡大小」。 |
| 移动了解压文件夹 | 从新位置重新运行 `Install.cmd`；使用主题时，再运行主题启用入口。 |

主题配置和日志保存在 `%LOCALAPPDATA%\ClosureCodexTheme`。请求结果中的 `startup` 表示本次启动方式：`direct` 为直接启动，`attached` 为接入已有主题窗口，`restarted` 为普通窗口重启后接入。

不要将 `work/companion-profile` 或 `work/companion-runtime` 当作缓存删除：前者是个人桌宠设置，后者是运行所需组件。另附的 `outputs/closure-pet` 是原生桌宠格式与离线预览，用法见[随附说明](../outputs/closure-pet/说明.txt)。

## 从源码构建与验证

源码环境需要 Node.js 22+ 执行测试。完整发行包的运行时已内置，普通用户无需安装 Node.js。

在项目根目录准备已通过清单校验的 Electron 45.4.1 Windows x64 运行时，放入 `work/companion-runtime/electron`，然后运行：

```powershell
& .\Build-Release.ps1 -Destination .\dist\v0.7.0
```

也可以使用[官方 Electron 压缩包](https://github.com/electron/electron/releases/download/v45.4.1/electron-v45.4.1-win32-x64.zip)：

```powershell
& .\Build-Release.ps1 -Version 0.7.0 -ElectronZip 'C:\Downloads\electron-v45.4.1-win32-x64.zip' -Destination .\dist\v0.7.0
```

构建会检查版本与运行时 SHA-256，打包三款软件的主题、DSH 联动插件和使用指南，生成 ZIP 与 `SHA256SUMS.txt`。不包含个人配置、测试缓存或宣传制作资料。插件子包分别保留自身版本号，主发行版本为 0.7.0。

```powershell
node --test tests/*.test.cjs
& .\tests\release.ps1
& .\tests\release-clean-install.ps1
```

`release.ps1` 验证 ZIP 的校验和、内容与源码一致性。`release-clean-install.ps1` 从实际 ZIP 解压到包含中文、空格与 `&` 的新目录，在空配置和无外部 Node.js 的 PATH 下，检查安装卸载、桌宠互动、主题注入及恢复；需要已安装 Store 版 Codex。报告位于 `work/release-clean-install`。

安装注册使用独立启动目录，功能检查使用独立后台配置。这些同机隔离检查不代表已经覆盖全新 Windows 系统、实际登录自启及其他硬件环境。

开发预览入口为 `tools/decoration-preview/Preview.cmd`。桌宠开发可用 `launch.cmd --demo` 打开测试窗口，`launch.cmd --canvas` 强制 Canvas 2D；`CLOSURE_ELECTRON_EXE` 可指定运行时，`CLOSURE_STATE_DIR` 可指定数据目录。
